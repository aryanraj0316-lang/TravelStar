# TravelStar — Conventions

This document is the single source of truth for cross-cutting conventions in this codebase. It is enforced everywhere, without exception, per `docs/REMEDIATION.md` §0.2. Any code that violates a rule here is a bug, not a style preference.

## 1. Product identity

The product is **TravelStar**, everywhere:
- `app.json`: `expo.name`, `expo.slug`, `expo.scheme`, `expo.android.package`, `expo.ios.bundleIdentifier`
- Root `package.json` name, backend `package.json` name
- All UI copy, the LICENSE, and any `about.tsx` copyright line

No other name (`Tourism`, `TravelConnect`, `TravelConnect India`, `travelconnect-backend`) may appear anywhere in source, config, or copy.

## 2. API response envelope

Every backend endpoint returns exactly one of these two shapes. No exceptions, no variations.

```ts
// Success
{ "ok": true, "data": T, "meta"?: { "cursor"?: string, "total"?: number } }

// Failure
{ "ok": false, "error": { "code": "TRIP_NOT_FOUND", "message": "Human readable", "details"?: unknown } }
```

- `error.code` is a `SCREAMING_SNAKE_CASE` member of a single exported union type shared by client and server.
- HTTP status is always meaningful: `400` validation, `401` unauthenticated, `403` unauthorised, `404` not found, `409` conflict, `422` business-rule violation, `429` rate limited, `500` unexpected.
- The client's `request()` unwraps `data` on `ok: true` and throws a typed `ApiError` on `ok: false`. It never returns `null` to signal failure.

## 3. Money

- Stored in Postgres as `Decimal @db.Decimal(12, 2)`. Never `Float`.
- Transported over the wire as a **string** (`"8500.00"`) to avoid JS float loss.
- Represented in the client by a single `Money` type and formatted only through one helper: `formatINR(value: Money): string` → `"₹8,500"`.
- Never format currency inline with template strings. No `₹${x.toLocaleString('en-IN')}` anywhere in the codebase — route it through the helper.

## 4. Dates and times

- Stored as `timestamptz`. Transported as ISO 8601 UTC strings.
- All display formatting goes through `formatDate`, `formatTime`, `formatRelative` in `src/lib/datetime.ts`. Timezone is `Asia/Kolkata` unless the user's device says otherwise.
- No ad-hoc `new Date(x).toLocaleTimeString([], {...})` or hand-written relative-time strings (`"14 mins ago"`) anywhere else.

## 5. IDs

- All entity IDs are UUIDs generated by the database. The client never invents an ID (`` `trip-${Date.now()}` `` is banned).
- Idempotency keys, where needed, are client-generated UUIDv4 and sent in an `Idempotency-Key` header.

## 6. Screen state machine

Every screen that loads remote data implements exactly four states, using one shared component set:

`<ScreenLoading />` · `<ScreenError onRetry />` · `<ScreenEmpty title action />` · content

No screen may render content while data is still `undefined`. No screen may show a spinner forever.

## 7. User feedback

- `Alert.alert` is banned — it no-ops on web, and this app ships web. Use a single cross-platform `<Dialog>` / `useConfirm()` and a `toast()` API in `src/lib/feedback.ts`.
- Success toast for every successful mutation. Error toast with `error.message` for every failure. No exceptions.

## 8. Design tokens

- **One** palette, in `src/constants/theme.ts`. No local `const C = { bg: '#060814', ... }` object in any screen.
- One canonical background color, one canonical set of near-duplicates resolved. Do not introduce a new one-off hex value; add a token instead.
- Spacing comes only from the `Spacing` scale. Radii from a `Radii` scale. Typography from a `Typography` scale — no inline `fontSize: 8.5`.

## 9. Naming

- Backend routes: `kebab-case` paths, plural resources: `/api/v1/trips/:tripId/join-requests`.
- TS files: `kebab-case.ts(x)`. React components: `PascalCase`. Hooks: `useThing`.
- One vocabulary for the domain: the entity is a **Trip**. Not a tour, route, group, or expedition — rename on sight.

## 10. Error handling

- `catch (e) {}` and `.catch(() => {})` are banned. Every caught error is either handled meaningfully, surfaced to the user, or logged with context and re-thrown.
- No mock data as a fallback for a failed request. Mock data may exist only behind an explicit `__DEV__ && process.env.EXPO_PUBLIC_USE_MOCKS === 'true'` flag, and must be visibly labelled in the UI when active.
- No hardcoded secrets, no hardcoded hosts, no hardcoded IDs.
- Dead code is deleted, not commented out.

## 11. Quality gates

Both root and `backend/` expose:

```json
"typecheck": "tsc --noEmit",
"lint": "eslint . --max-warnings=0",
"format": "prettier --write ."
```

All three must pass before a change is considered done. Every bug fix ships with a regression test; every new endpoint ships with an integration test.
